# 시스템 설계 (Architecture)

무선 ECG 패치 환자 실시간 모니터링을 위한 소켓 채널 라우터의 구조 설계 문서입니다.
프로토콜/API 상세는 [API.md](API.md), 화면 기능과 JSON 스키마는 [FRONTEND.md](FRONTEND.md)를 참고하세요.

## 0. 역할 분담 원칙 (한눈에)

| 데이터 | 주인 | 이유 |
|---|---|---|
| 환자/패치/예약/시계열 메트릭 (정적·영속) | **DB API (SQLite, 병원별 파일)** | 조회·이력의 단일 소스 |
| 에뮬레이터發 다이내믹 업데이트 (meta, 패치 폐기, 예약 상태) | **라우터가 ingest 로 받아 DB 로 중계** | 모든 채널 데이터가 라우터를 통과 — 업데이트 경로 일원화 |
| 파형 (고속 시계열, ~2,000 pkt/s) | **라우터가 파일로 직접 보관** | SQLite 에 부적합, 라우터가 유일한 통과 지점 |
| 환자 프로필 명단 (1만 명) | **에뮬레이터 자체 보유** (`data/patients.json`) | 에뮬레이터는 DB 와 독립 동작해야 함 |

## 2. 데이터 흐름과 싱크 (핵심 설계)

1. 에뮬레이터가 **채널(패치)당 TCP 연결 1개**로 `meta`(최초 + 60초 주기) / `ecg` 패킷(seq 포함)을 전송.
   `meta` 에는 병원 ID 와 **프로필 번호**(얼굴 이미지 지정)가 함께 실린다.
2. 라우터 Ingest 는 패킷을 ① **채널별 서큘러 버퍼(512패킷)** 에 보관, ② 분석 서버로 forward,
   ③ **파형 저장 태스크**로 전달(파일 보관), ④ meta/폐기/예약은 **DB Link 로 중계**.
3. 분석 서버는 **100ms 지연** 후 `{channel_id, seq, hr, events}` 반환.
4. 라우터는 `(channel_id, seq)` 로 버퍼에서 **원본 파형을 꺼내 병합** → 출력.
   파형·HR·이벤트가 항상 같은 seq 로 정렬된다. seq 보다 오래된 버퍼 항목(응답 유실분)은 폐기.
5. 병합 패킷은 채널이 속한 **모든 그룹** + **게이트웨이/채널 구독자**에게 브로드캐스팅.

장애 대응 경로:

| 상황 | 동작 |
|---|---|
| 분석 서버 다운 | **패스스루 모드**: 버퍼링 중단, 파형을 `hr=null` 로 즉시 통과. 2초 백오프 재접속. **다운타임은 ms 단위로 누적 실측**되어 가동 시간 카드/타임 로그에 표시 |
| 분석 지연 (스톨/저속) | **플러셔(100ms 주기)** 가 500ms 초과 대기 패킷을 무분석 방출 → 파형 연속성 보장. `analysis_delay` 이벤트 기록(3초 쿨다운 집계) |
| ingest 소켓 끊김/리셋 | EOF·에러 동일 경로로 정리, `ingest_disconnected` 이벤트. 명시적 제거는 `channel_close` |
| 5초 무패킷 | 분석 서버 watchdog 이 `disconnected` 이벤트 발행, 재개 시 `reconnected` |
| 비정상 종료 잔재 | `POST /api/channels/prune` — 해제 상태 채널을 레지스트리에서 일괄 정리 (DB 리셋/병원 전환 후 어드민이 자동 호출) |

## 3. 그룹핑 모델

- 그룹 = `{ id, name, description, owner, criteria, include, exclude }` (`groups.json` 영속화)
- `criteria`: 속성 조건. 키 = `building|floor|ward|zone|room|doctor|department|nurse`,
  한 키의 여러 값은 **OR**, 키 사이는 **AND**. `include`/`exclude` 는 채널 수동 지정(exclude 최우선).
- criteria 와 include 가 모두 비면 **전체 매칭** — 기본 `all` 그룹이 이 규칙이며
  **붙박이**(목록 최상단 고정, 삭제 403 거부)다.
- 한 채널은 매칭되는 **모든 그룹에 동시 소속** (다중 브로드캐스팅).
- 멤버십 재계산 시점: ① meta 수신/갱신(트랜스퍼 포함) ② 그룹 CRUD. 변경분은 diff 되어
  그룹별 `membership {join|leave}` 로 구독자에게 push. WS 구독 시작 시 `snapshot` 즉시 전송.
- **기본 그룹 자동 시딩**: 어드민의 DB 리셋이 완료되면 실제 채널 분포에서 값을 뽑아
  작은 규모→큰 규모 순으로 10개를 생성한다 (환자 최다 병실/구역, 담당 환자 최다 간호사/주치의,
  층, 병동, 진료과 상위 2, 건물, 복수 병동(또는 복수 층) 통합). 각 그룹의 `owner` 는
  **주요 사용자**로 채워진다 — 담당 간호사/주치의 본인, 층·로비 전광판, 수간호사, 중앙관제 등.

## 4. 병원/공간 모델 (다병원)

- 병원 정의는 두 곳이 짝을 이룬다 (id 로 연동):
  - 에뮬레이터 `patients.py` 의 `HOSPITALS`: 건물/층 범위/층당 병실 수/병실당 병상 수 + **패치 프리픽스**
  - 어드민 `web/admin/src/floorplans/<id>.json`: 평면도(벡터)와 표시 구조
- 기본 제공: **서울 A 병원** (A/B동 × 2~15층 × 12실 × 6병상, 프리픽스 `SA`),
  **부산 B 병원** (W/E동 × 9~21층 × 20실 × 4병상, 프리픽스 `BB`).
- **병상 슬롯 저층 순차 충전**: 채널 수가 늘면 위층이 순서대로 열린다. 병실당 최대 병상 수 보장.
- 파생 규칙: 구역 `Z1/Z2`(병실 열의 좌/우 절반), 병동 `W1/W2/W3`(층 밴드 3분할),
  주치의(환자 20명당 1명), 간호사(건물×층×구역당 1명) — 규모에 비례해 자동 증가.
- **채널 ID = 패치 ID** 는 병원 프리픽스로 전역 유일 (`SA-0001`, `BB-0001`, 재고 `PT-SA-1001`).

### 병원 전환 = 일시 중단(suspend), 재생성 아님

`POST :7500/hospital?id=` 로 전환하면:

1. 이전 병원 채널을 `channel_close(reason="suspend")` 로 종료 — 라우터 레지스트리에서는
   제거되지만 **DB 의 패치는 폐기(retire)하지 않는다**. 데이터가 그대로 보존된다.
2. 새 병원의 **DB 명단을 로드**해 채널을 만든다 (응답의 `source:"db"`).
   DB 가 비어 있을 때만 신규 생성 폴백 (`source:"generated"`).
3. 복귀 시 동일한 환자 명단이 그대로 복원된다.

전환 타이밍 레이스 방지 장치:
- meta/channel_close/appointment 메시지에 **병원 ID 를 실어** DB API 가 op 단위로
  정확한 병원 DB 에 기록 (현재 병원 폴링 5초 지연과 무관).
- DB API reconcile 루프는 보정 직전에 현재 병원을 재확인하고, 라우터 레지스트리에
  그 병원 채널(프리픽스)이 실제로 있을 때만 동작 — 전환 과도기에 이전 병원의
  in_use 패치를 잘못 폐기하는 것을 방지.

## 5. DB 계층 (병원별 SQLite)

`db-api/` 는 **병원마다 독립된 SQLite 파일**(`hospital-<id>.db`)을 관리한다.

| 테이블 | 내용 |
|---|---|
| `patients` | 환자 메타 + 프로필(profile_no/성별/생년월일/혈액형/병변 JSON) + 채널 연결 |
| `patches` | 패치 라이프사이클: `in_stock`(재고) → `in_use`(meta 수신) → `retired`(퇴원/교체) |
| `appointments` | 예약: `reserved` → `in_progress`(검사 시작, 복귀 예상 기록) → `done`(복귀) / `cancelled` |
| `metrics` | 10초 샘플 시계열 (pkt/s, 유실율, 채널 수, GW 장애, 분석 링크 상태) — 35일 보존 |
| `events` | 타임 로그 이벤트 (patch_deployed/retired, downtime start/end, gateway_down/up, db_reset) |

- 라우터가 **TCP 7601 NDJSON push** 로 갱신 (`upsert_patient` / `retire_patch` / `upsert_appointment`).
  op 에 병원 ID 가 있으면 그 병원 DB 로, 없으면 현재 병원 DB 로 라우팅.
- 백그라운드 루프: 병원 폴링(5초) / 시계열 샘플러(10초, 다운타임·GW 이벤트 기록) /
  reconcile(10초 — 라우터에 없는 in_use 패치 retire, **15분 경과 미실행 예약 취소**).
- **DB 리셋** (`POST /db/reset`): 병원별 DB 파일 삭제 → 재생성 → 재고 50개 시드 →
  에뮬레이터 `/roster` 로 200명 명단 시드. 어드민이 이어서 에뮬레이터 리로드,
  라우터 prune/stats 리셋, 기본 그룹 시딩까지 체인으로 실행한다.

## 6. 게이트웨이 모델

게이트웨이는 **공간에 고정 매핑**되며 같은 공간의 패치들이 공유한다:

| 공간 | 게이트웨이 ID | 배치 단위 |
|---|---|---|
| 병실 | `GW-{건물}{층}-{병실}` | 병실당 1대 |
| 복도 | `GW-{건물}{층}-{구역}-HALL` | 건물×층×구역당 1대 |
| 화장실 | `GW-{건물}{층}-{구역}-WC` | 건물×층×구역당 1대 |
| 검사실 | `GW-{건물}1-EXAM` | 건물당 1대 (1층) |

- 현재 게이트웨이/공간은 모든 `ecg` 패킷에 실리고, 라우터 레지스트리와 출력 스트림에 반영된다.
- 게이트웨이 상태는 에뮬레이터가 **전용 ingest 연결로 2초마다 push** → `/api/gateways` → 어드민 표시.

### 환자 이동 (천천히 걷는 전제)

이동은 순간이동이 아니라 **단계별 도보 여정**이다. 두 종류가 있다:

**① 임의 이동** (채널당 평균 20분에 1회):

```
병실 → 복도 보행(20~60초) → 목적지 체류 → 복도 보행(20~60초) → 병실 복귀
                             ├ 화장실: 1~3분
                             ├ 검사실: 3~8분
                             ├ 복도 산책: 1~3분
                             └ 병문안: 같은 층 다른 병실 1~3분
```

- 임의 이동은 **복귀 시각을 예측할 근거가 없으므로** UI 에 복귀 예정을 표시하지 않는다.
- **병문안**으로 다른 병실에 있는 동안은 입실이 아니라 **이동 중** 상태로 표기된다
  (동선 타임라인에는 "N호 방문", 평면도에는 방문 병실 위치에 이동 색상 칩).

**② 예약 기반 이동** (검사/진료):

```
예약 생성(2~10분 뒤 시작) → 시간 도래 → 복도 보행 → 검사실 체류(예약 소요 시간)
  → 복도 보행 → 병실 복귀 (status: reserved → in_progress → done)
```

- 소요 시간이 예약에 정의되어 있으므로 **복귀 예상 시각(eta_return)이 추정 가능**하다.
- 에뮬레이터 스케줄러가 평균 12초에 1건씩 예약 없는 환자에게 랜덤 예약을 잡고,
  상태 변화를 라우터 경유로 DB 에 기록한다 (혈액검사/심전도/X-ray/CT/외래 진료/재활 치료).

**동선 이력**: 채널마다 공간 전환을 감지해 최근 40구간(`move_log`)을 보관하고,
`GET :7500/journeys` 로 지나온 구간/현재 위치/다음 예약을 노출한다 → 동선 타임라인 UI 의 소스.

## 7. 환자 프로필 · 얼굴 아바타 (1만 명)

- `emulator/data/patients.json` — **에뮬레이터 자체 보유** (DB 독립 동작 원칙).
  `scripts/gen-profiles.py` 로 생성. 채널 인덱스로 결정적 배정
  (서울 = 1번부터, 부산 = 5001번부터 → 병원 간 프로필 중복 없음).
- **이름**: `emulator/names_ko.py` 의 성별/출생 연대별 다빈도 이름 시드 데이터.
  고령 환자는 영자/숙자/병호 계열, 젊은 환자는 서연/민준 계열이 나온다.
  주치의(Dr.)/간호사(N.) 이름도 같은 풀을 사용한다.
- **얼굴**: `web/admin/public/faces/<profile_no>.png` (256×256, 총 1만 장, 약 100MB 미만).
  `python_avatars`(Avataaars) + `resvg` 렌더링, 시드 고정 결정적.
  성별(여: 롱헤어/번+얇은 눈썹, 남: 짧은 커트/대머리+수염)과
  연령(62세+ 회색 머리)이 구분된다. 실제 인물 아님.
- meta 의 `profile_no` 가 라우터/DB/프런트로 흐르며 리포트 모달이 얼굴을 지정한다.
- 알려진 렌더링 이슈 대응: python_avatars 의 `fill=""` 는 resvg 가 검정으로 칠하므로
  `none` 으로 치환, 원형 밖 투명 영역은 같은 계열 파스텔로 채움 (`scripts/avatar_gen.py`).

## 8. 파형 파일 저장 (라우터, 8시간 세그먼트 보관)

모든 채널의 파형이 라우터를 통과하므로 저장 주체도 라우터다
(고속 시계열 쓰기는 SQLite 에 부적합 — DB 는 메타데이터 전용).

- 배치: `router-server/waves/<channel_id>/<epoch_8h_block>.bin` — 채널별 **8시간 세그먼트**.
  8시간 분량이 채워지면 다음 8시간짜리 파일이 새로 생성된다. **삭제는 없다**
  (실제 워킹 시나리오 — 전 구간 보존, 장기 보관 이관은 운영 정책의 영역).
- 레코드(LE): `[ts_ms u64][seq u64][sample_rate u16][n u16][samples i16 × n]`
  (샘플 ×1000 정수 양자화 — mV 해상도 유지, NDJSON 대비 1/4 크기)
- 기록은 전용 태스크가 mpsc 로 받아 처리 (ingest 핫패스 비차단), 5초 주기 flush.
- 조회: `GET /api/wave/{ch}/info` (가용 범위/용량),
  `GET /api/wave/{ch}?mode=raw|overview&from_ms=&to_ms=` —
  raw 는 120초 상한(세그먼트 배열, 수신 공백은 분리), overview 는 구간 min/max 버킷 요약.
- 어드민 리포트 모달의 **전문 파형 뷰어**가 이 API 를 사용한다
  (ECG 모눈 배경, 개요 클릭=15초, 블록 드래그=구간 전체, 좌우 팬).

## 9. 장애 시뮬레이션 모델

**전제: 장애는 패치 레벨 또는 게이트웨이 레벨에서만 발생한다. 전체 네트워크 장애는 없다.**

| 레벨 | 종류 | 파라미터 |
|---|---|---|
| 패치 | 접속 불량 (소켓 끊김 후 재접속, **미전송 구간은 seq 스킵 → 유실 카운트**) | 불량 채널(idx%7==3) 평균 45초, 일반 평균 10분 |
| 패치 | 약신호 (진폭 감소 + 노이즈) | 평균 2분 간격, 4~10초 지속 |
| 패치 | 이동 중 신호 배리에이션 | 3~10초 구간별 35% 약신호 |
| 게이트웨이 | 장애 — 해당 공간 전 패치 업링크 중단 | **60~120초 지속**, 동시 장애 ≤ 전체의 5% |
| 게이트웨이 | 동구역 간섭 | 구역 내 **약 35% 패치만** 약신호 + 간헐 끊김 |
| 분석 엔진 | 개별 응답 저속 | 2% 확률로 0.3~2초 |
| 분석 엔진 | 스톨 (응답 폐기) | 1~3분 간격, 75%는 3~10초 / 25%는 61~90초 |
| 분석 엔진 | 크래시 | 5~10분 간격, **리스너까지 내려가 15~45초 재기동** → 라우터 패스스루 + 다운타임 실측 누적 |

패킷 유실은 라우터가 **seq 갭**으로 감지해 누적 카운트한다 (에뮬레이터는 미전송 구간의
seq 를 건너뛰어 유실을 재현). ECG 패킷 카드와 타임 로그에 반영된다.

## 10. 채널 상태 모델

| 우선순위 | 상태 | 판정 | 색 |
|---|---|---|---|
| 1 | 해제 | 소켓 끊김 (`connected=false`) | 회색 |
| 2 | **수신중단** | 소켓 유지 + **3초 이상 무패킷** (`stale`) — 게이트웨이 장애의 가시화 | 빨강 |
| 3 | 약신호 | 마지막 패킷 `quality=weak` | 황색 |
| 4 | 이동 중 | `moving=true` | 남색 |
| 5 | 정상 | — | 녹색 |

## 11. 라우터 내부 모듈과 동시성

```
router-server/src/
├── main.rs           # 부트스트랩 (설정, 태스크 spawn)
├── lib.rs            # router_core 라이브러리 (이식 가능)
├── config.rs         # 환경변수 설정 (주소/경로/버퍼/파형 세그먼트)
├── protocol.rs       # 와이어 메시지 타입 (meta/ecg/appointment/…, Patient 프로필 필드 포함)
├── registry.rs       # 채널 레지스트리 + 서큘러 버퍼 + stale/유실 판정 (DashMap)
├── grouping.rs       # 그룹 정의/매칭/영속화
├── state.rs          # AppState: 병합·브로드캐스트·멤버십 diff·이벤트 링·다운타임 누적·플러셔
├── ingest.rs         # TCP 수신 (채널당 태스크) — 분석 forward + DB 중계 + 파형 저장 분기
├── analysis_link.rs  # 분석 서버 클라이언트 (재접속, 패스스루 전환)
├── db_link.rs        # DB API push 클라이언트 (재접속, 큐 드레인)
├── wave_store.rs     # 파형 8h 세그먼트 파일 기록/조회 (전용 태스크)
├── output.rs         # WS 구독 (그룹/게이트웨이/채널 3종 필터)
├── admin_api.rs      # REST API (+ prune, wave 조회)
└── sysmon.rs         # CPU/디스크 모니터링 (Windows API)
```

- 채널당 ingest 태스크 1개. 분석 링크/DB 링크는 단일 연결 + `mpsc` 큐.
- 출력은 전역 `broadcast`(4096) 1개에 봉투(`그룹목록, 게이트웨이, 채널, 직렬화 JSON`)를 실어
  보내고, WS 세션이 자기 구독과 교집합만 전달. 직렬화는 패킷당 1회.
- 실측: 400채널에서 수신 1.1MB/s · 송신 2.4MB/s · 1,914pkt/s · CPU 8% · 메모리 41MB.

## 12. 디스플레이 모델

- 물리 디스플레이(센트럴 모니터)는 평면도 JSON 의 `display` 공간으로 배치.
- 디스플레이 → 그룹 매핑은 라우터가 `displays.json` 으로 영속화 (`/api/displays`).
- Patch Map 에서 디스플레이 클릭 → 그룹 지정 → 뷰어 링크(`:5173/?group=<id>`).

## 13. 실서비스 전환 시 고려사항

- NDJSON → length-prefixed 바이너리(protobuf 등)로 대역폭 ~70% 절감
- 분석 링크 단일 연결 → 채널 해시 샤딩 / 출력 broadcast → 그룹별 샤딩
- groups/displays JSON → DB, 라우터 다중 인스턴스 시 멤버십 이벤트 버스(NATS 등)
- 파형 세그먼트의 장기 보관 이관(아카이브 스토리지) 및 압축 정책
- 게이트웨이 상태를 실제 게이트웨이 헬스체크로 대체
- 평면도 JSON 을 실제 병원 도면 좌표로 교체 (렌더러는 그대로 사용 가능)
- 예약을 실제 HIS/EMR 연동으로 대체 (현재는 에뮬레이터 랜덤 생성)
